## 一、Dejavu Web APM 性能监控平台【核心项目】

### 项目背景

Dejavu 是哔哩哔哩内部的 Web APM（应用性能监控）平台，用于监控 Web 应用的错误、性能和用户行为数据。负责平台前端开发与优化工作，涵盖错误监控、性能分析、数据可视化、UI升级等多个核心模块的迭代开发。

### 模块一：错误告警分析系统

**1. 错误监控架构设计与实现**
- 独立完成 5 种错误类型（JS运行时错误、Promise拒绝、API调用失败、资源加载失败、白屏检测）的告警分析页面开发
- 基于 Pinia Store 按错误类型分离设计，实现 useAlarmJsStore、useAlarmApiStore、useAlarmWhiteStore 等专项 Store，提升状态管理的可维护性
- 梳理 alarm-analysis 工作流程，设计通用组件与个性化组件的分离架构

**2. 错误详情表格重构**
- 主导 error-data-table 组件的全面重构，统一 5 种错误类型的表格展示逻辑
- 实现错误详情的多维度聚合展示（按错误类型、时间、用户影响范围等），支持嵌套数据的展开与收起
- 解决 Naive UI 折叠面板与可展开表格的交互冲突，通过事件委托精确控制展开触发区域，避免事件冒泡问题
- 修复 resource 模块 message 字段错误、白屏检测下 resource 相关错误板块的数据渲染问题

**3. AI 修复建议集成**
- 集成 AI 流式输出功能（基于 WebSocket），为错误提供智能修复建议
- 实现源代码映射功能（getErrorSourceFile()），支持错误定位到具体代码行
- 解决 Vite 构建环境下流式输出效果丢失问题

**4. 性能优化与问题排查**
- 针对告警分析页面，优化 API 调用策略：通过 Store 统一管理公共数据，消除组件间重复请求
- 使用 markRaw() 优化 ECharts 实例的响应式处理，避免不必要的性能开销
- 实现 ECharts 响应式容器设计：使用百分比宽度 + vh 高度 + resize 方法，支持图表随浏览器窗口自适应
- 优化图表生命周期管理，确保组件卸载时正确销毁 ECharts 实例，避免内存泄漏
