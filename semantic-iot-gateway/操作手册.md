# Semantic IoT Gateway 操作手册

这份手册是给“不懂协议、只想把设备接进来”的人写的。

你不需要先理解 `Modbus TCP` 和 `BACnet/IP` 的细节，只需要把它们理解成两种“设备通讯方式”：

- `Modbus TCP`
  - 常见于电表、能耗表、PLC、部分网关设备
- `BACnet/IP`
  - 常见于楼宇自控、空调控制器、AHU/DDC 控制器

## 1. 这套工具是干什么的

它是装在建筑现场电脑上的“边缘采集器”。

它做的事情是：

1. 连现场设备
2. 按配置读取点位
3. 把数据统一整理
4. 批量发给后面的 ECS 服务器

它**不是**前端页面，也**不是** TalkAlways 主站本体。

## 2. 使用前要满足什么条件

必须满足这几个前提：

1. 这台电脑能访问现场设备所在的局域网。
2. 你至少知道一部分设备的 `IP`。
3. 你至少知道设备使用的是 `Modbus TCP` 还是 `BACnet/IP`。
4. 最好手里有点位表。

如果你已经知道设备 `IP`，可以直接跳过“扫网段”。

## 5. 最推荐的使用顺序

第一次使用，按这个顺序做：

1. 打开 `配置`
2. 填网关基础配置
3. 新增设备
4. 给设备新增点位
5. 保存配置
6. 到 `运行` 页启动
7. 看日志确认是否连通

如果你不确定设备 IP，再先去 `探测` 页做一次探测。

## 6. 配置页怎么用

`配置` 页里又分两块：

- `可视化配置`
- `JSON`

建议你平时只用 `可视化配置`，不要手改 JSON。

### 6.1 网关基础配置

这部分是整个边缘网关自己的信息。

主要字段：

- `Gateway ID`
  - 这台边缘电脑的唯一名字
  - 例子：`building-edge-01`
- `Site ID`
  - 站点名字
  - 例子：`eagle-edu`
- `Batch Size`
  - 每次往 ECS 发送多少条数据再打包
  - 不知道就先用 `20`
- `Flush Interval`
  - 就算没攒满多少条，隔多少秒也发一次
  - 不知道就先用 `2`
- `Stdout`
  - 是否在本地日志里打印输出内容
  - 调试时可以开着

### 6.2 HTTP Push

这是边缘端往 ECS 上报的地址。

字段说明：

- `HTTP Push`
  - 勾上表示启用上报
- `endpoint`
  - ECS 接口地址
  - 例子：`https://你的服务器/api/iot/ingest/batch`
- `auth token`
  - 后续如果 ECS 需要鉴权，就填这里
- `HTTP Timeout`
  - 请求超时时间，先用 `5.0`
- `Verify TLS`
  - HTTPS 证书校验

如果现在 ECS 接口还没做好，可以先不启用 `HTTP Push`，先本地调试。

### 6.3 Spool

这是“断网缓存”。

意思是：

- 如果 ECS 暂时收不到数据
- 采集器会先把批次临时存在本地
- 网络恢复后再补发

建议先保持开启。

字段说明：

- `Spool`
  - 是否启用本地缓存
- `path`
  - 本地缓存数据库路径
  - 默认：`data/spool.db`
- `Spool Retry(s)`
  - 间隔几秒重试发缓存
- `Spool Batch`
  - 每次补发多少批

### 6.4 本地 BACnet 运行参数

这部分只和 `BACnet/IP` 相关。

如果你暂时只接 `Modbus TCP`，这部分先保持默认即可。

主要字段：

- `Local Address`
  - 本机在现场网段里的地址
  - 例子：`192.168.10.8/24`
- `Instance`
  - 本机这个 BACnet 应用自己的编号
- `Name`
  - 本机 BACnet 名字
- `Vendor`
  - 厂商 ID，当前默认 `999`
- `Network`
  - 一般先用 `0`
- `Foreign`
  - 只有跨网段或特殊 BACnet 场景才填
- `TTL`
  - Foreign 模式下的租期，默认即可

## 7. 怎么新增设备

设备列表在左边。

按钮有两个：

- `新增 Modbus`
- `新增 BACnet`

### 7.1 新增 Modbus 设备

点 `新增 Modbus` 后，会自动生成一个模板设备。

然后填写右侧 `设备详情`：

- `Device ID`
  - 设备唯一标识
  - 例子：`power-meter-01`
- `Name`
  - 设备显示名
  - 例子：`1号总电表`
- `Building ID`
  - 所属建筑编号
  - 这个要和 TalkAlways 后续业务编码保持一致
- `Device Type`
  - 自己定义的设备类型
  - 例子：`power_meter`
- `Host`
  - 设备 IP
  - 例子：`192.168.10.20`
- `Port`
  - 一般是 `502`
- `Enabled`
  - 勾上才会真正采集
- `Poll(ms)`
  - 轮询周期，毫秒
  - 例子：`5000`
- `Timeout(s)`
  - 超时秒数
  - 例子：`3`

Modbus 专属字段：

- `Unit ID`
  - 也叫站号、从站号
  - 常见值是 `1`
- `Address Style`
  - `offset` 或 `reference`

这两个很关键：

- 如果厂家文档写的是 `40001、40002` 这种形式，优先选 `reference`
- 如果厂家文档写的是从 `0、1、2` 开始，优先选 `offset`

填完点 `保存设备`。

### 7.2 新增 BACnet 设备

点 `新增 BACnet` 后，填写：

- `Device ID`
- `Name`
- `Building ID`
- `Device Type`
- `Host`
  - 设备 IP
- `Port`
  - 一般是 `47808`
- `Enabled`
- `Poll(ms)`
- `Timeout(s)`

BACnet 专属字段：

- `Device Instance`
  - 设备实例号
  - 如果你知道就填，不知道可以先留空

填完点 `保存设备`。

## 8. 怎么新增点位

先在设备列表里选中一个设备，然后在下面的点位区域操作。

按钮有：

- `新增点位`
- `删除点位`
- `保存点位`

### 8.1 所有点位通用字段

无论 Modbus 还是 BACnet，都有这些字段：

- `Point ID`
  - 点位唯一标识
  - 例子：`main_power_kw`
- `Tag`
  - 标准业务名字
  - 例子：`Eagle_Edu_MainPower`
- `Standard Tag`
  - 语义标签
  - 例子：`power`、`temperature`、`humidity`
- `Unit`
  - 单位
  - 例子：`kW`、`degC`
- `Scale`
  - 缩放系数
  - 例子：原始值是 1254，真实值应该是 125.4，就填 `0.1`
- `Offset`
  - 偏移量
  - 一般填 `0`
- `Deadband`
  - 死区过滤
  - 变化太小就不重复上报
  - 例子：温度可填 `0.2`
- `Enabled`
  - 勾上才采这个点

### 8.2 Modbus 点位怎么填

Modbus 点位需要再填：

- `Register Type`
  - `holding`
  - `input`
  - `coil`
  - `discrete`
- `Address`
  - 寄存器地址
  - 例子：`40001` 或 `0`
- `Data Type`
  - `bool`
  - `uint16`
  - `int16`
  - `uint32`
  - `int32`
  - `float32`
  - `float64`
  - `string`
- `Reg Count`
  - 占用多少寄存器
  - `float32` 常见填 `2`
- `Byte Order`
  - 字节序，先试 `big`
- `Word Order`
  - 字序，先试 `big`

如果读出来的值明显不对，优先检查：

1. `Address Style`
2. `Register Type`
3. `Data Type`
4. `Byte Order / Word Order`
5. `Scale`

### 8.3 BACnet 点位怎么填

BACnet 点位需要再填：

- `Object Type`
  - 例子：`analog-value`、`analog-input`、`binary-value`
- `Object Instance`
  - 对象实例号
- `Property`
  - 通常填 `present-value`
- `Array Index`
  - 大多数情况留空

如果你不确定，最常见的开始方式是：

- `Object Type = analog-value`
- `Property = present-value`

## 9. 探测页怎么用

探测只做“辅助确认”，不是必须步骤。

如果你已经知道设备 IP，可以跳过这一页。

### 9.1 Modbus 探测

有两种方式：

- 填 `Hosts`
  - 例子：`192.168.10.20,192.168.10.21`
- 填 `CIDR`
  - 例子：`192.168.10.0/24`

说明：

- `Port`
  - 一般是 `502`
- `Timeout`
  - 探测超时时间
- `Limit`
  - 扫网段时最多探测多少个地址

点击 `开始探测` 后，下面会显示结果。

注意：

- Modbus 探测目前只说明“这个 IP 的 502 端口能不能连”
- 它**不代表**点位表一定正确

### 9.2 BACnet 探测

字段说明：

- `Local Address`
  - 本机现场网卡地址
- `Target Address`
  - 不填就是广播探测
- `Timeout`
  - 等待返回时间
- `Vendor ID / Instance / Device Name / Network / Foreign / TTL`
  - 一般先用默认值

点击 `开始探测` 后，如果现场网段正常，会在结果里看到设备地址和实例号。

## 10. 运行页怎么用

点 `启动网关` 后：

- 程序会按已启用设备开始轮询
- 日志区会显示运行信息

点 `停止网关` 后：

- 程序会停止采集

如果日志里看到：

- `Gateway started with X enabled devices`

说明程序已经开始跑了。

## 11. 最简单的上手方式

如果你是第一次用，建议只做一个设备、一个点位先打通。

### 例子：接一个 Modbus 电表

1. 打开 GUI
2. 在 `配置 -> 可视化配置`
3. 填：
   - `Gateway ID = building-edge-01`
   - `Site ID = eagle-edu`
4. 点 `新增 Modbus`
5. 填设备：
   - `Device ID = power-meter-01`
   - `Name = 1号总电表`
   - `Building ID = Eagle_education_Cassie`
   - `Device Type = power_meter`
   - `Host = 192.168.10.20`
   - `Port = 502`
   - `Enabled = 勾上`
   - `Unit ID = 1`
   - `Address Style = reference`
6. 点 `保存设备`
7. 点 `新增点位`
8. 填点位：
   - `Point ID = main_power_kw`
   - `Tag = Eagle_Edu_MainPower`
   - `Standard Tag = power`
   - `Unit = kW`
   - `Scale = 0.1`
   - `Register Type = holding`
   - `Address = 40001`
   - `Data Type = float32`
   - `Reg Count = 2`
9. 点 `保存点位`
10. 点 `保存`
11. 到 `运行` 页点 `启动网关`
12. 看日志

如果没报错，说明链路已经通了。

## 12. 常见问题

### 12.1 启动后没数据

优先检查：

1. 设备 `Enabled` 有没有勾上
2. 点位 `Enabled` 有没有勾上
3. 设备 IP 对不对
4. 现场电脑和设备是不是在同一网段
5. 端口对不对

### 12.2 Modbus 能连上，但值不对

优先检查：

1. `Address Style`
2. `Address`
3. `Register Type`
4. `Data Type`
5. `Scale`
6. `Byte Order`
7. `Word Order`

### 12.3 BACnet 探测不到设备

优先检查：

1. 现场电脑是否接入正确网段
2. `Local Address` 是否填对
3. 设备是否真的启用了 `BACnet/IP`
4. 网络里是否限制了广播

### 12.4 点了保存但下次打开没了

检查：

1. 你有没有点击顶部 `保存` 或 `另存为`
2. 当前保存的文件路径是否正确
3. `配置文件` 输入框里的路径是不是你想要的那个文件

## 13. 你真正需要记住的几件事

如果你只记最重要的内容，记这几条就够了：

1. 现场电脑必须能访问设备局域网。
2. 已知设备 IP 时，不需要扫网段。
3. 一台设备先配一个点位，跑通后再批量加。
4. Modbus 读数不对时，先怀疑地址、数据类型、缩放和字节序。
5. 保存后再启动，启动后看日志。
